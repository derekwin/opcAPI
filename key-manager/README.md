# API Key 管理

管理员打开 Key 管理页，创建和查看完整 Key、设置有效期和额度、追加 Token、停用或删除。停用保留记录，删除同时移除密钥和它的用量记录。应用只有一个进程，Key 和额度保存在服务工作目录下的 keys.json。

公网管理页为 http://203.0.113.10:18181/ 。公网 HTTP 会明文传输登录凭据和 API Key。也可在管理员电脑建立 SSH 隧道。

```sh
ssh -N -p 22022 -L 127.0.0.1:18181:/run/key-manager/admin.sock root@203.0.113.10
```

使用隧道时，浏览器打开 http://127.0.0.1:18181/ 。尚未创建管理员时，公网管理页和隧道入口都会显示注册表单。首个管理员注册成功后，后续访问使用已有账号登录。页面右上角可改密码、退出登录。改密码后所有会话失效，登录会话有效期为 12 小时，服务重启后需重新登录。

管理员账号文件 `admin-account.json` 与 Key 文件同目录，权限为 0600，口令使用随机盐和 PBKDF2-SHA256 保存。

公网客户将 Base URL 设为 http://203.0.113.10:18180/v1 。客户也可通过仅允许转发到服务器 127.0.0.1:18180 的 SSH 账号建立隧道，将 base_url 设为 http://127.0.0.1:18180/v1，使用管理员发放的 Key 请求模型列表、单模型详情或聊天补全。聊天支持普通响应、流式响应、多候选和工具调用。请求体默认上限为 32 MiB，可用 `-max-body-bytes` 调整。

网关按 Key 检查有效期、每分钟请求数、并发数和累计 Token。创建 Key 时可勾选「不限累计额度」，已有 Key 可在「管理」中切换。不限额度的 Key 直接转发聊天，并按实际用量累计 Token。切回限额时填写新的剩余额度，历史用量继续保留。

有额度上限的 Key 在每次聊天前先调用 SGLang 的分词接口计算输入用量，再预留输入和输出额度。客户端可以指定输出长度，也可以省略并使用模型默认值。预留额度按模型上下文或客户端请求的长度计算，多个候选共享 Key 的可用余额。生成后按 SGLang 返回的 usage 结算。上游连接失败或返回 HTTP 错误会释放预留额度。流中断时只结算已收到的用量，客户端按自己的 stream_options 接收用量。密钥文件包含完整 Key，权限为 0600。

部署前将 `guide.html` 中的示例地址 `203.0.113.10`、SSH 端口和模型名改为实际值。进入 `key-manager/` 后运行 `go build -o key-manager .`。systemd 配置见 `key-manager.service`，上游模型地址默认是 http://127.0.0.1:18000。

管理页的“模型接入公告”可直接复制给客户。网关的 `/guide` 提供同一份接入说明，包含客户端配置和 SSH 转发命令。
